# Threat model

Scope: fictional records in a single-clinic portfolio application. Assets: synthetic demographics, notes, attachments, encryption keys, provider keys and audit integrity. Actors: unauthenticated visitors, authenticated users of each role, compromised clients, malicious note text, privileged project operators and external providers.

| Threat                                | Implemented mitigation                                                                                                | Residual risk                                                                                                         |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| UI role tampering / direct SDK access | Server-side current claims; deny all direct Firestore/Storage access                                                  | A bug in Admin SDK callable authorization can bypass rules                                                            |
| Patient ID substitution               | Patient owner lookup before every scoped action                                                                       | Clinic-wide clinician access is intentionally broad                                                                   |
| Missing read audit                    | Callable logs before returning records                                                                                | Auth failures and malformed inputs rejected before action parsing are not in app audit; platform logs must cover them |
| Audit manipulation                    | No client audit writes; mutation audit atomic where possible                                                          | Project admins can edit/delete logs; no WORM export                                                                   |
| Database contact-field disclosure     | AES-256-GCM for phone/address; per-field/record AAD; secret key                                                       | Name/DOB/notes plaintext at application layer; platform at-rest protection applies                                    |
| API key theft                         | Keys bound to Functions via Secret Manager                                                                            | Project IAM and developer machines remain trusted                                                                     |
| AI disclosure                         | Known-identifier and regex redaction, synthetic-only policy, no prompt telemetry                                      | Redaction cannot guarantee de-identification; external providers receive residual text                                |
| Prompt injection / hallucination      | Fixed system instruction; output rendered as plain text; explicit clinician save                                      | No clinical correctness guarantee or comprehensive output validator                                                   |
| File abuse                            | Role check, 750KB cap, PDF signature and extension validation, private object, attachment disposition, 60s signed URL | No malware scanning; PDF magic alone does not make a file safe; URL is a bearer capability until expiry               |
| AI spend abuse                        | 6 requests/user/minute; 60 total operations/user/minute; 5 max instances                                              | Fixed-window bursts and many accounts; not a billing hard cap                                                         |
| Signing races                         | Firestore transaction checks open state before append/sign                                                            | No amendments/correction workflow                                                                                     |

No real PHI is permitted. HIPAA compliance is an organizational and operational determination, not a feature list. Before clinical use: legal assessment and appropriate BAAs across infrastructure and AI vendors, risk analysis, least-privilege IAM, vendor retention evaluation, stronger tenant/care-team isolation, MFA, verified logging/retention, incident response, backups/restores, consent/release controls, key rotation, malware scanning, penetration testing and independently validated workflows would be required. This app is not presented as satisfying those requirements.
